## 阶段 1：PDF 引擎适配层（核心基石）★

**目标**：把 PyMuPDF 封装成稳定的 `PdfEngine` 接口，**这是全项目最重要的隔离层**。完成后上层再不碰 pymupdf。

### 任务清单
- [ ] 建 `engines/pdf_engine.py`、`engines/exceptions.py`
- [ ] 实现 `PdfEngine` 核心方法（先做读取类）：
  - [ ] `open(path) -> DocumentHandle`（打开、异常处理、密码 PDF 提示）
  - [ ] `page_count(doc)`
  - [ ] `metadata(doc)`（标题、作者、页数等）
  - [ ] `render_page(doc, page_num, zoom) -> PixmapData`（渲染为位图）
  - [ ] `extract_text(doc, page_num) -> str`
  - [ ] `search(doc, query) -> list[SearchHit]`（返回页码+矩形）
- [ ] 定义返回数据结构（`PixmapData`、`SearchHit`、`DocumentHandle` 用 dataclass）
- [ ] **下载测试样例 PDF** 到 `tests/fixtures/samples/`（纯文本、扫描件、表格、加密）
- [ ] 写 `tests/unit/engines/test_pdf_engine.py`：每个方法对应测试
- [ ] 边界测试：损坏 PDF、加密 PDF、空 PDF、超大页码

### 验收标准
- ✅ `PdfEngine` 所有读取方法实现并测试通过
- ✅ **测试覆盖率 ≥ 90%**（engines 层是地基，必须严测）
- ✅ mypy 类型检查无错
- ✅ **整个项目只有 `engines/` 出现 `import pymupdf`**（用 grep 验证）

### 设计要点
- 返回**不可变数据**（dataclass + frozen），避免上层误改引擎内部状态
- 异常分层：`PdfEngineError` 基类 → `PasswordRequiredError`、`CorruptPdfError` 等，上层按类型处理

## 阶段 4：连续滚动 + 缩放（性能攻坚）★

**目标**：流畅浏览大文档（几十上百页）。**这是全项目最大的技术难点**，因为 PyMuPDF 非线程安全。

### 任务清单
- [x] ~~建 `workers/render_worker.py`：单专用渲染 QThread~~（已废弃：渲染改为主线程直接渲染受控文档，
  否则批注/编辑等内存改动看不到，见 CHANGELOG 0.0.2「所见即所得渲染」）
- [ ] 建 `utils/cache.py`：LRU 页面缓存（缓存最近 N 页的 QPixmap）
- [ ] 改造 `pdf_view.py` 为连续滚动视图：
  - [ ] 监听滚动位置，只渲染视口前后几页（按需渲染）
  - [ ] 占位符：未渲染的页先显示灰底/缩略图
  - [ ] 快速滚动时取消过时的渲染任务
- [ ] 缩放：Ctrl+滚轮 / 快捷键，支持适应宽度/实际大小
- [ ] 缩略图侧栏 `gui/widgets/thumbnail_bar.py`（低 DPI 预渲染）
- [ ] 性能测试：用 100+ 页大文档验证流畅度

### 验收标准
- ✅ 100 页 PDF 滚动不卡顿（目测 ≥ 30fps）
- ✅ 内存稳定（LRU 缓存生效，不无限增长）
- ✅ 缩放流畅
- ✅ **Document 对象绝不出现在主线程**（代码审查 + 日志断言验证）

### 关键风险
- PyMuPDF 非线程安全 → 严格遵守"Document 只活在渲染线程"
- 跨线程传 QPixmap 要确认 Qt 的线程亲和性（用信号槽，Qt 自动排队连接）

## 贯穿全程的质量纪律

1. **每个阶段结束 = 可运行 + 测试全绿 + 一次 git 提交**。绝不留"做到一半"的状态。
2. **测试与功能同步写**。不为"赶进度"跳过测试——跳过的测试会在阶段 4/7（最难的部分）加倍偿还。
3. **类型注解强制**。mypy 在 pre-commit 和 CI 中拦截。
4. **小步提交**。一个功能一次提交，commit message 清晰（遵循 Conventional Commits）。
5. **不优化过早，也不欠债太久**。阶段 3 先跑通再优化性能（阶段 4 专门做）。
6. **遇到不确定的先验证**（像前面验证 PyMuPDF 线程安全那样），不要凭想象写代码。

## 风险预案

| 风险 | 触发阶段 | 应对 |
|---|---|---|
| PyMuPDF 线程崩溃 | 阶段 4 | 严守单线程持 Document；加日志断言验证 |
| 滚动性能不达标 | 阶段 4 | 降级策略：降 DPI、增大缓存、缩略图占位 |
| 批注坐标准确性 | 阶段 7 | 坐标转换独立成模块 + 专项测试 |
| RapidOCR 打包体积 | 阶段 8/10 | 模型按需下载 或 预打包，权衡体积 |
| Word→PDF 依赖 LibreOffice | 阶段 9 | 作为可选功能，检测+引导安装 |
| pdf2docx 停维护 | 阶段 9 | 适配器隔离，留替换接口 |
