# 打包与发布

> 适用版本：Lumen 0.0.6 当前开发分支。产物：程序目录 `dist/PDFReader/` 与安装程序 `dist/PDFReader-Setup-<版本>.exe`。

## 1. 流程

```bash
make check        # 1. 质量门禁全部通过
make icon         # 2. 图标有改动时重新生成 app.ico（可选）
make installer    # 3. PyInstaller 打包 + NSIS 生成安装程序
dist/PDFReader/PDFReader.exe --selftest   # 4. 冻结环境自检（结果写入 %USERPROFILE%\.pdfreader\selftest.json）
```

发布前检查清单：

- [ ] 版本号三处一致：`pyproject.toml`、`src/pdfreader/__init__.py`、`scripts/installer.nsi`
- [ ] `CHANGELOG.md` 已把 `[Unreleased]` 整理为版本条目
- [ ] `make check` 全绿
- [ ] `--selftest` 输出 `"ok": true`（pdf_engine / convert_deps / ocr_engine / ai_deps / research_deps；ai_deps 会真正加载 `_ssl` 并建一个 HTTPS 客户端）
- [ ] 在真机安装后手工验证：打开 / 批注 / 保存、加密文档、OCR、导出、「打开方式」、高分屏显示

## 2. PyInstaller（`scripts/build_windows.py`）

* **onedir**（目录版）：启动快，不必每次解压；作为安装程序的输入。约 410 MB。
* 隐藏导入：rapidocr_onnxruntime、onnxruntime、cv2、pdf2docx、pdfplumber、openpyxl、PySide6.QtPrintSupport。
* `--collect-all`：rapidocr_onnxruntime（OCR 模型 `*.onnx`）、onnxruntime（原生 DLL）、pdf2docx、pdfplumber、
  openpyxl、shapely。
* 打包后自动校验：exe 存在、OCR 模型已打包、onnxruntime DLL 存在、`libcrypto-3-x64.dll` / `libssl-3-x64.dll` / `libffi-8.dll`
  与解释器自带版本逐字节一致（不一致即打包失败）。打包时解释器的 `DLLs` 目录排在 PATH 最前——
  否则在 Git Bash 等环境里会收进 `Git\mingw64\bin` 下同名但不兼容的 OpenSSL，安装后所有 AI 请求报
  「DLL load failed while importing _ssl」。
* 中间产物 `build/` 可随时删除（`make clean`）。

## 3. NSIS 安装程序（`scripts/installer.nsi`）

* 编译器查找顺序：系统 PATH → electron-builder 缓存 `%LOCALAPPDATA%\electron-builder\Cache\nsis\nsis-*\makensis.exe`
  → `C:\Program Files (x86)\NSIS`。本机使用的是放在 electron-builder 缓存中的官方 NSIS 3.10。
* 安装内容：
  * 默认安装到 `C:\Program Files\PDF Reader\`（需要管理员权限，可在向导中修改）；
  * 桌面与开始菜单快捷方式；
  * 「应用和功能」中的卸载项（含版本、大小、图标）；
  * 注册为 `.pdf` 的「打开方式」候选（`OpenWithProgids` + `Applications\PDFReader.exe`），**不抢默认程序**；
* 卸载会删除程序目录、快捷方式与上述注册表项；用户数据 `%USERPROFILE%\.pdfreader\`（设置、日志、阅读位置）保留。
* 覆盖安装：直接运行新安装程序即可，不需要先卸载。
* 安装程序名称、程序目录与 exe 名仍为「PDF Reader / PDFReader」；界面品牌为 Lumen。

## 4. 应用图标

`scripts/make_icon.py` 把 `gui/theme/icons.py` 中的 Lumen 标志（赤陶圆角方块 + 白色衬线「l.」）渲染为
16–256 px 七个尺寸的 `src/pdfreader/resources/icons/app.ico`，供 exe、安装程序与快捷方式使用。窗口内的图标由
同一份 SVG 在运行时渲染，两者保持一致。

## 5. 版本历史说明

品牌更名为 Lumen 后版本号从 **0.0.1** 重新开始；`CHANGELOG.md` 中「Lumen 0.0.1」之下的 0.0.4 / 0.0.2 / 0.0.1
属于旧的「PDF Reader」版本线。

## 6. 原生构建与研究依赖

Windows 安装包仍运行 uv run python scripts/build_windows.py --installer，保留解释器 OpenSSL DLL 字节校验。新增 collect-all：bibtexparser、regex、docx（含默认模板），以及 QtTextToSpeech 隐藏导入。冻结自检增加 research_deps，实际创建中文 DOCX、解析 BibTeX、运行正则并加载朗读模块；不访问真实 AI、不开启音频。

scripts/build_desktop.py 只能在目标系统原生执行，--dry-run 只显示命令。Windows 复用已有 DLL 约束构建，Linux/macOS 用原生 PyInstaller 目录包；自检成功后生成 dist/Lumen-<version>-<platform>-<arch>.zip。macOS 未提供商业签名与公证，Linux 需要系统图形/凭据服务。

.github/workflows/build-desktop.yml 通过 workflow_dispatch 手动运行三个原生系统的核心回归、构建和冻结自检。Linux 在独立 D-Bus 会话中启动系统密钥环，使用临时 CI 密码，不使用空凭据后端绕过自检。配置提交不能替代实际工作流成功记录。

Release 应列出实际安装包、校验和、测试与自检结果、功能入口、会话缓存/明文导出边界、AI 核对限制，以及未提供的签名、自动安装更新、云同步和移动端。
