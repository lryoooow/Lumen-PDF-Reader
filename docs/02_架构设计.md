# 架构设计

> 适用版本：Lumen 0.0.2。面向开发者：分层与依赖规则、关键机制与不可破坏的约定。
> 文件级说明见 [03_项目结构](03_项目结构.md)，开发流程见 [05_开发与测试](05_开发与测试.md)。

## 1. 技术栈

| 层面 | 选型 | 说明 |
| --- | --- | --- |
| 语言 / 包管理 | Python ≥ 3.10（开发用 3.13）/ uv | `uv.lock` 锁定依赖 |
| GUI | PySide6（Qt 6.8–6.9），Fusion 基底 + 代码生成的 QSS | 主题见 `gui/theme/` |
| PDF 引擎 | PyMuPDF **1.28.x**（锁定小版本） | 依赖其内部 `_get_textpage` 与日志守卫补丁，升级需复核 |
| OCR | RapidOCR（onnxruntime） | 可选依赖，缺失时功能禁用 |
| 格式转换 | pdf2docx（Word）、pdfplumber + openpyxl（Excel） | 只在 `services/` 中使用 |
| AI 助读 | httpx（OpenAI 兼容接口，流式 SSE）、keyring（API Key 存系统凭据管理器） | 只在 `services/ai/` 中使用 |
| 阅读模式滤镜 | numpy | 仅 `gui/widgets/pdf_view.py` |
| 打包 | PyInstaller（onedir）+ NSIS | 见 [06_打包与发布](06_打包与发布.md) |

许可证 AGPL-3.0-or-later（与 PyMuPDF 一致）。

## 2. 分层

```
gui/          PySide6 界面：主窗口、视图、面板、对话框、主题、动效
  │ 调用
controllers/  协调界面与业务；失败原因记录在 last_error，供界面展示
  │ 调用
core/         领域模型 Document / Page：修改状态、撤销保存点、页数同步（纯 Python）
  │ 依赖协议
engines/      引擎协议 PdfEngine + PyMuPDF 实现（项目里唯一 import pymupdf 的地方）

services/     OCR、格式转换、笔记导出、AI 助读（纯 Python；AI 只做网络与文本处理，不碰 PDF）
workers/      QThread：搜索 / OCR / 转换（各自打开文件副本）、AI 请求（只做网络）
utils/        日志、LRU 缓存、文本工具、Qt 位图桥接
config/       用户设置持久化
```

依赖方向：`gui → controllers → core → engines`；`services` / `workers` 可被 `gui` 使用。

### 2.1 三条铁律（`tests/unit/test_layering.py` 用 AST 扫描强制）

1. `core/`、`services/` 不得 import PySide6 或 pymupdf。
2. 只有 `engines/pdf_engine.py` 可以 import pymupdf（`main.py --selftest` 探测依赖除外）；
   pdf2docx / pdfplumber / rapidocr 只出现在 `services/`。
3. PyMuPDF 非线程安全：子线程只跑 `workers/` 的搜索 / OCR / 转换；**页面渲染在主线程**直接渲染受控文档。
   AI 请求的文字在主线程取好、拼成消息，`AiWorker` 只做网络 I/O。

## 3. 关键机制

### 3.1 坐标：一律「可见帧」

引擎对外的矩形与点都在 `page.rect` 坐标系（已应用 /Rotate），与 `render_page` 位图逐像素对应。
批注与内容流在 PDF 内部按「未旋转帧」存储，由引擎在边界折算：

* 读：`_textpage()` 走 PyMuPDF 内部 `Page._get_textpage`——公开的 `get_text*` / `search_for` 会临时改写
  /Rotate，在开启撤销日志时于旋转页上必然报错；
* 写：`_unrotated_point / _unrotated_rect` 折算回未旋转帧，文字与图片补 `rotate=page.rotation` 保持正立；
* GUI 只做「÷ zoom、减去页在场景中的偏移」，**不处理旋转**。

改动坐标相关代码必须跑 `tests/unit/engines/test_rotated_pages.py`。

### 3.2 撤销与修改状态

* `open()` 必开 PyMuPDF 日志（journal）；每次修改由 `PyMuPdfEngine._op()` 包成一个可撤销操作。
* PyMuPDF 1.28.0 的日志守卫 `ENSURE_OPERATION` 在日志开启后必然报错，引擎模块加载时将其替换为空实现
  （修改始终在 operation 内进行，C 层仍会拦截越界写入）。
* `Document` 记录「保存点」（保存 / 打开时的历史位置）：撤销 / 重做回到保存点即视为未修改；
  在保存点之前做新编辑会截断含保存点的重做分支，保存点随即作废（之后一律视为已修改）。
* 合并文档需要从内存重开（`insert_pdf` 与日志不兼容），合并后撤销历史清空；合并前先完整校验对方文件，
  失败时不动当前文档。

### 3.3 渲染与视图

* `PdfView` 在 `QGraphicsScene` 上纵向排列所有页（水平居中、页间距 24px、柔和阴影），只为可见页发出
  `renderRequested`；主窗口在主线程渲染并回填。
* 渲染倍率 = 逻辑缩放 × 屏幕缩放比（高分屏清晰），单页像素上限 24 MP；缓存按页数（30）与总字节（384 MB）
  双重上限，离开视口且被淘汰的页换回占位。
* 缩放范围 10%–800%，缩放 / 编辑后保持「页 + 页内相对位置」；「当前页」= 视口中露出最多的页。
* 阅读模式在位图层套用设计稿的 CSS 滤镜矩阵（夜间 invert(0.9)+hue-rotate(180°)，护眼 sepia(0.35)+brightness(0.97)）。

### 3.3.1 多标签页

* 一个标签（`gui/document_tab.DocumentTab`）= 一份文档的**全部私有状态**：`DocumentController`（含撤销日志）、
  `PdfView`（渲染 / 取词 / 链接缓存、选区、动画）、`AiAssistant` + `AiPanel`、后退 / 前进历史、OCR 线程与结果。
  功能区、侧边栏、搜索浮层、状态栏、引用卡由 `MainWindow` 共用，切换时 `_leave_tab` 收尾旧标签
  （取消搜索、复位工具、落定滚动动画、释放渲染位图），`_show_tab` 按新标签重新填充。
* `MainWindow._controller / pdf_view / ai_panel / _ai / _ocr_*` 都是指向**当前标签**的属性；视图与面板的信号经
  `_for_tab` 门控——只有当前标签的信号会被处理，后台标签发出的渲染请求、批注操作一律丢弃。
* 始终至少有一个标签：没有文档时是一个空标签（标签栏隐藏，窗口显示文献库首页），打开文件优先复用它；
  新开的标签只有打开成功才加入，失败即丢弃。
* OCR 全局同时只跑一个，结果按 `sender()` 回到发起它的标签；关闭标签时回收其 OCR 线程、停止其 AI 请求，
  AI 线程未结束前标签暂存在 `_parked_tabs`，结束后才销毁。AI 设置全局共享（`settingsApplied` → 其他标签 `adopt_settings`）。
* 关闭窗口：逐个切到有改动的标签询问保存（任一取消即中止），再关闭所有文档、等待所有线程。

### 3.4 后台线程与快照

* 搜索 / OCR / 转换在 `QThread` 中各自打开文件；有未保存改动时，主线程先把内存文档写成**唯一命名的快照**
  （`%TEMP%\pdfreader_snapshots_<pid>\`），快照失败则取消操作，绝不退回磁盘旧内容。
* 加密文档：打开时的密码保存在内存中的 `Document`，传给所有后台线程与转换库。
* 搜索逐页检查取消标志；新一轮搜索、切换 / 关闭文档时回收旧线程（结果不再进界面）；
  退出前等待所有线程结束（运行中的 QThread 被析构会让进程崩溃）。
* OCR 默认 200 DPI，位图长边上限 2000 px；取消与完成分别发不同信号。
* 退出时只删除本进程登记过的快照文件，目录为空才删除目录。

### 3.5 保存与加密

| 场景 | 行为 |
| --- | --- |
| 存回原文件 | 增量保存，`PDF_ENCRYPT_KEEP` 保留加密 |
| 「另存为」选中原文件 | 自动转为增量保存（PyMuPDF 不允许整份覆盖正在打开的文件） |
| 打开时被修复过的文件 | 无法增量保存：给出原因，引导另存为 |
| 整份保存（另存为 / 快照） | 文档仍带 /Encrypt 时用 `KEEP`；加密已丢失（合并后）则按原密码 AES-256 重新加密并回填原始 /P 权限 |
| 文档只剩一页 | 禁止删除最后一页（0 页的 PDF 无法保存） |

### 3.6 文本

* 取词：PyMuPDF 按空白切词，整行中文是一个「词」；引擎用字符框把含中日韩字符的词拆成单字，
  选择 / 高亮 / 批注原文提取都基于拆字后的词表。
* 拼接：同一行相邻两段文本，任一侧是 CJK 字符时不加空格（`utils/text.join_words`）。
* 「去换行复制」：合并行尾连字符断词与排版换行，保留空行分段（`utils/text.clean_copied_text`）。

### 3.7 AI 助读

```
PdfView 右键 / 框选 ─┐
AiPanel 动作 / 提问 ─┼→ gui/ai_assistant.AiAssistant ──→ workers.AiWorker ──→ services/ai/client.ChatClient
功能区              ─┘   (确认 · 取文字 · 拼消息)         (QThread，可取消)      (httpx 流式 SSE)
```

* `services/ai/`：`provider`（预设、`ai.json` 读写）、`keystore`（keyring 封装，测试注入内存后端）、
  `client`（流式解析、错误中文化、Key 脱敏、`cancel()` 关闭响应即刻中断）、`context`（分块、BM25、`[p.N]` 链接化）、`prompts`。
* 只用 OpenAI Chat Completions：不自动补 `/v1`（用户填什么用什么，404 时提示）；只发必要参数（`temperature` 留空不发）。
* 引用页码为 1 起的物理页；面板把 `[p.N]` 渲染成 `cite:N` 链接，超出页数的保持纯文本。
* 每个标签一个 `AiAssistant`（对话互不串）；换文档 / 关闭时停止请求、清空对话；退出前等所有标签的 AI 线程结束。

### 3.8 错误上报

* 控制器捕获异常，原因写入 `DocumentController.last_error` 并记日志；界面在操作返回 False 时展示原因。
* 只读查询（取词、链接、目录、批注列表）失败时返回空结果并记日志，不打断阅读。
* 面向用户的消息只含文件名，完整路径与堆栈只写日志（`~/.pdfreader/pdfreader.log`）。
* 全局未捕获异常由 `main.global_exception_handler` 记录并弹出对话框。

## 4. 不可破坏的约定

1. 坐标一律可见帧（§3.1）。
2. 文本读取只走引擎的 `_textpage()`，不直接调用会改写 /Rotate 的 PyMuPDF API。
3. 渲染在主线程、渲染受控文档；后台线程只读快照或原文件。
4. 编辑后保持当前页（`setup_document(..., keep_page=…)` / `reading_position()`），不得把「无当前页」当成第 1 页。
5. 保存 / 导出 / 快照不得静默写明文、丢加密、退回旧内容或吞异常。
6. 用户可见的失败不得静默：`except` 后要记日志或把原因交给界面。
7. API Key 只进系统凭据管理器，不得写入 `settings.json` / `ai.json` / 日志；测试不得访问真实网络。
7. 界面颜色走主题令牌（`gui/theme/palette.py`），PDF 页面本身保持白色。
