# 修复记录（2026-10-13，承接《问题排查记录》）

本文件记录排查报告之后的实际改动与验证结果，仅写**已经落地并跑过测试**的内容。
每个条目都给出文件/测试位置，便于复核。

## 本轮（续查后）改动

### 1. 引擎补齐 PNG 编码与图片转 PDF（P0-3 配套）

- `engines/base.py` 协议新增 `pixmap_to_png(data) -> bytes`、`images_to_pdf(paths, out) -> int`；
  `engines/pdf_engine.py:263-302` 给出实现。
- `pixmap_to_png` 修正了原先的错误调用形式：PyMuPDF 的构造签名是
  `Pixmap(colorspace, width, height, samples, alpha)`，第 5 个位置参数是 **alpha 而不是 stride**；
  旧写法 `Pixmap(n, w, h, stride, samples)` 必然抛 `Unrecognised args for constructing Pixmap`。
  现实现：`n` → 色彩空间映射（未知通道直接 `RenderError`），`stride != width*n` 时逐行取紧凑样本，
  异常消息截断到 200 字符（PyMuPDF 会把整幅像素样本拼进消息，可达数 MB）。
- `images_to_pdf` 把图片合成 PDF，空列表会因 PyMuPDF「cannot save with zero pages」抛 `FileOpenError`。

### 2. OCR 线程不再直接使用 PyMuPDF，且不再静默跳过

`workers/ocr_worker.py`：

- 删除 `_ocr_pixmap_data` 里的 `import pymupdf`（违反「只有 engines 知道 PyMuPDF」），
  改为 `self._engine.pixmap_to_png(pixmap_data)`。
  **这是本轮最有价值的回归点**：旧实现每页都抛异常，而 `_ocr_page` 把
  `PdfEngineError` 一律吞掉返回 `None` → 整本 OCR「跑完但零结果」，GUI 无任何提示。
- `run()` 开头检查 `OCR_AVAILABLE`，未装依赖时直接 `ocrFailed("OCR 功能不可用：…")`，
  不再等到第一页才在 OCR 服务内部抛错。
- `_ocr_page` 的错误处理收窄为「只吞 `RenderError`（单页渲染失败）」，并补 `_logger.warning`；
  PNG 编码失败属引擎级故障，向上抛出，由 `run()` 转成 `ocrFailed`，
  避免"所有页都被跳过却报成功"。
