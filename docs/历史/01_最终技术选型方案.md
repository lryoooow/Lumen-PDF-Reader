## 三、渲染桥接标准模式（核心代码模板）

```python
import pymupdf
from PySide6.QtGui import QImage, QPixmap

doc = pymupdf.open("file.pdf")
page = doc[0]
pix = page.get_pixmap(matrix=pymupdf.Matrix(2, 2), alpha=False)  # 2x 缩放

# alpha=False → RGB888；alpha=True → RGBA8888
fmt = QImage.Format_RGB888 if pix.n == 3 else QImage.Format_RGBA8888
qimg = QImage(pix.samples, pix.width, pix.height, pix.stride, fmt)
qpixmap = QPixmap.fromImage(qimg.copy())   # .copy() 关键：让 QPixmap 持有数据
label.setPixmap(qpixmap)
```

**三个必须注意的坑**：
1. `pix.stride` 要传给 `bytesPerLine`，不能用 `width*n`（会错位）
2. `QImage(samples,...)` 不复制数据，必须 `.copy()` 或保持 `pix` 存活
3. `alpha=False` 省内存/省通道，除非需要透明背景（如批注叠层）

## 四、批注功能（PyMuPDF 原生支持）

```python
import pymupdf
doc = pymupdf.open("in.pdf")
page = doc[0]

# 高亮（搜索关键词并高亮）
page.add_highlight_annot(page.search_for("关键词"))
# 手写/自由画线（ink，传点序列）
page.add_ink_annot([[pymupdf.Point(50,50), pymupdf.Point(150,80)]])
# 文本便签
page.add_text_annot(pymupdf.Point(100,100), "批注内容")
# 框选/矩形
page.add_rect_annot(pymupdf.Rect(10,10,100,100))

doc.save("out.pdf")   # 保存批注
```

**Qt 侧交互**：用户在画布上鼠标拖动得到像素坐标 → 除以 zoom 换算成 PDF 点坐标（1点=1/72英寸）→ 调对应 `add_*_annot` → 重新渲染该页。`get_pixmap()` 默认渲染已有批注。

**功能覆盖**：高亮/下划线/删除线/波浪线、手写、文本便签、矩形/圆形框选、图片印章 —— 全部支持创建+渲染+读取+修改+删除+保存。

## 五、性能架构（最大难点，必须做对）

### 🔴 PyMuPDF 非线程安全
官方 Issue #107 明确："PyMuPDF is not threadable"。多 QThread 共享同一个 Document 会崩溃。官方推荐 `multiprocessing` 而非 `threading`。

### 推荐架构：单专用渲染线程 + 信号回主线程

```
[UI 主线程]                      [渲染线程 QThread]
  QGraphicsView/QScrollArea         持有 Document 对象
       │                              │
       │── "渲染第N页" 任务 ──→──── 队列取任务
       │                              │ get_pixmap → QImage
       │←── Signal(QPixmap) ──────────┘
       │
   按需渲染可见页 + LRU 缓存(几十页)
```

**必须做的优化**：
- 按需渲染（只渲染视口前后几页）
- LRU 缓存最近 N 页的 QPixmap
- 缩略图预渲染（低 DPI 占位，后台出高清）
- 快速滚动时取消旧任务

**好消息**：PyMuPDF 渲染本身极快（比同类快约 4.5 倍），瓶颈在图像搬运和 UI，不在渲染。

| **OCR（中文）** | **RapidOCR** | **Apache-2.0** | **★最佳选择** |

### RapidOCR 为什么是最佳选择
- **Apache-2.0**（兼容 AGPL，无传染）
- **PP-OCRv5 模型，中文效果等同 PaddleOCR 顶配**
- **~15MB 模型内置 wheel，离线开箱即用**（vs PaddlePaddle 200MB+）
- **纯 pip 安装，无系统级依赖**（vs Tesseract 要装第三方构建）
- **活跃维护（v3.9.2，2025），7.2k stars，1400万下载**
- 有配套 `RapidOCRPDF` 直接处理 PDF 整页 OCR

## 九、风险与应对

| 风险 | 应对 |
|---|---|
| pdf2docx 已停维护 | 代码层做好封装隔离（独立模块/适配器），便于将来替换 |
| Word→PDF 需 LibreOffice | 作为可选依赖，运行时检测 soffice，提供安装引导 |
| PyMuPDF 非线程安全 | 用单专用渲染线程，不用多线程共享 Document |
| 连续滚动性能 | 按需渲染 + LRU 缓存 + 缩略图占位 + 滚动取消机制 |
| RapidOCR 首次加载模型慢 | 应用启动时预热，或懒加载 |
