## 1. 问题清单（按严重度）

### P0：会损坏/丢失用户数据，或核心功能完全不可用

#### R3-01　编辑后「当前页」丢失 → 再次删除/旋转/加水印会作用到第 1 页（实测）

```
跳到第 4 页后 current_page_num = 3
旋转后 current_page_num = 0 → _current_page_for_edit() = 0
第一次旋转后各页角度 = [0, 0, 0, 90, 0, 0, 0, 0]
第二次旋转后各页角度 = [90, 0, 0, 90, 0, 0, 0, 0]   ← 期望第 4 页变 180，实际转了第 1 页
撤销后 current_page_num = None
```

根因：`PdfView.setup_document`（`gui/widgets/pdf_view.py:637`）把 `_current_page` 置为 None，只有真正发生滚动时
`_update_current_page` 才会重新算；`_refresh_after_edit` / `_reload_after_change` 都会调 `setup_document`，
而 `MainWindow._current_page_for_edit`（`main_window.py:609`）用 `current_page_num or 0` 把 None 静默变成第 1 页。
「删除页」也走这条路径——确认框写的是「删除第 1 页」，用户不细看就会删错页（撤销可救，但已是数据误操作）。
同类：OCR「识别当前页」（`:845`）、上一页/下一页（`:468`）也用 `or 0`。

#### R3-02　有未保存改动时导出：默认输出落在临时快照目录，退出时被整个删除（实测）

```
导出源    = %TEMP%\pdfreader_snapshots_24048\snapshot_cf2d0d168b2b.pdf
默认输出  = %TEMP%\pdfreader_snapshots_24048\snapshot_cf2d0d168b2b
默认输出位于快照目录内 = True      （_cleanup_snapshots 会 rmtree 整个目录）
```

根因：`MainWindow._on_export`（`:939`）把快照路径直接交给 `ExportDialog`，对话框用 `source.parent / source.stem`
作默认输出（`export_dialog.py:90`），标题还显示「源文件：snapshot_xxx.pdf」；
`_cleanup_snapshots`（`:599`）退出时 `shutil.rmtree(快照目录)`，用户导出的 docx/txt/png 一并被删。
附带：手输/默认路径**不做覆盖确认**（只有点「浏览…」才有系统确认），多页图片的 `stem_N.png` 也无确认直接覆盖。

#### R3-03　加密 PDF 在 GUI 中仍然完全不可用（第二轮 R2-P0-1 的 GUI 半边从未落地）（走查 + grep）

- `MainWindow._open_path`（`:1060`）只调 `open_file(Path(path))`；`_on_open_failed` 对 `NEEDS_PASSWORD` 只弹警告。
  `grep password src/pdfreader/gui` 无任何结果——**全项目没有密码输入框**。
- 即使能打开：`SearchWorker.setup` / `OcrWorker.setup` 从不传密码；`ConvertService` 的 `engine.open(source)`、
  `pdf2docx.Converter`、`pdfplumber.open` 都不带密码；快照按 `PDF_ENCRYPT_KEEP` 保持加密 →
  搜索 / OCR / 导出对加密文档**必然失败**。
- 第二轮报告第 3 节把 1-1 列为批次 1，但第 6–8 节只记录了批次 2–4 的执行；CHANGELOG 只写了引擎的「加密保留」。

#### R3-04　脏标记：保存后撤销再做新编辑，重做回去被误判为「已保存」→ 关闭时不提示，改动丢失（实测）

```
保存后 is_modified = False saved_pos = 2
新分支编辑后 is_modified = True
新分支 undo+redo 后 is_modified = False   ← 内容已与磁盘不同
```

根因：`Document._refresh_modified_from_history`（`core/document.py:382`）只比较「历史位置 == 保存位置」。
在保存点之前做新编辑会截断 redo 分支，保存点对应的内容已不复存在，但 `_saved_position` 仍是 2。

#### R3-05　删掉唯一一页后文档无法保存（Ctrl+S 与另存为都失败），只能放弃全部改动（实测）

```
删除唯一一页：成功，page_count = 0
0 页文档保存 → FileOpenError: cannot save with zero pages
```

无论引擎、控制器还是 GUI 都没有拦截「删除最后一页」。
