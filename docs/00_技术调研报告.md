# PDF 软件开源技术选型调研报告（2025-2026）

> 调研日期：2026-07-23 ｜ 目标：为「多功能 PDF 阅读器/编辑器」选择可复用的开源框架
> 核心原则：**许可证商业友好 + 成熟活跃 + 直接可用或易于二次开发**

---

## 〇、一句话结论

| 你的情况 | 推荐组合 |
|---|---|
| **想闭源做商业产品，追求极致性能（首选）** | **PDFium（渲染）+ Qt 6（框架）+ PDF4QT（参考骨架）** |
| **团队是 Web/前端，想快速做出功能丰富的跨平台软件** | **PDF.js + Electron** |
| **想极致轻量、现代技术栈、敢尝鲜** | **PDFium(WASM/Rust FFI) + Tauri 2.0** |
| **只做 Windows、团队是 C#** | **PDFium + WPF（PDFiumSharp / Syncfusion 社区版）** |
| **只想做"套壳"，不自己造处理逻辑** | **Stirling-PDF（MIT 后端）+ 任意桌面壳** |

**许可证红线（最重要）**：
- ✅ 商业闭源安全：**PDFium(BSD)**、**PDF.js(Apache 2.0)**、**PDFBox(Apache 2.0)**、**qpdf(Apache 2.0)**、**pypdf(BSD)**、**PaddleOCR(Apache 2.0)**、**Tesseract(Apache 2.0)**
- ⚠️ 有条件可用：**Qt(LGPL，须动态链接)**、**pikepdf(MPL，文件级传染)**、**PDF4QT(LGPLv3，动态链接)**
- ❌ 闭源商业慎用（强传染或需买授权）：**MuPDF / PyMuPDF(AGPL)**、**iText 7(AGPL)**、**Ghostscript(AGPL，商业授权约 $25k/年)**、**Poppler(GPL)**、**SumatraPDF / Okular 等 GPL 应用**

## 一、PDF 渲染 / 阅读引擎对比

| 引擎 | 许可证 | 语言 | 商业闭源 | 保真度/性能 | 最佳场景 |
|---|---|---|---|---|---|
| **PDFium** | **BSD** ✅ | C++ | ✅ 完美 | ★★★★★ Chrome 同款 | **闭源商业桌面/跨平台首选** |
| **PDF.js** | **Apache 2.0** ✅ | JS | ✅ | ★★★ 大文档弱 | **Web / Electron 查看** |
| **MuPDF** | **AGPL** ⚠️ | C | ❌ 需买授权 | ★★★★ | 开源项目 / Python 提取(PyMuPDF) |
| **Poppler** | **GPL** ⚠️ | C++ | ❌ 链接即传染 | ★★★ | Linux/Qt 桌面、开源 |

### 1. PDFium ⭐ 商业首选

- **官方**：[github.com/chromium/pdfium](https://github.com/chromium/pdfium)
- **许可证**：BSD-style（无传染性，闭源可放心用）
- **背景**：Google 维护（驱动 Chrome，不可能停更），底层源自福昕 Foxit
- **能力**：高速渲染、低内存、XFA 表单、文本搜索/选择/复制、书签、栅格化、安全沙箱
- **预编译**：官方不提供二进制，用社区 [bblanchon/pdfium-binaries](https://github.com/bblanchon/pdfium-binaries)（NuGet `bblanchon.PDFium` 等，几乎所有跨语言 binding 都基于它）
- **缺点**：原生 C/C++，文档稀缺，API 陡峭
- **多语言 Binding**：
  - Rust：[pdfium-render](https://crates.io/crates/pdfium-render) ~0.5.x
  - Python：[pypdfium2](https://pypi.org/project/pypdfium2/) 5.x（ABI 级，内嵌二进制）
  - Dart：pdfium_dart（Flutter FFI）
  - JS/WASM：[@embedpdf/pdfium](https://www.embedpdf.com/docs/pdfium/introduction)
  - C#/.NET：PDFiumSharp
  - C++：直接链接；Qt 官方 Qt PDF 模块底层就是它

### 2. PDF.js ⭐ Web/Electron 首选

- **官方**：[github.com/mozilla/pdf.js](https://github.com/mozilla/pdf.js/) ｜ [mozilla.github.io/pdf.js](https://mozilla.github.io/pdf.js/)
- **许可证**：Apache 2.0（商业友好）
- **背景**：Mozilla 维护，Firefox 内置 PDF 查看器
- **能力**：纯 Web 解析+渲染、注释、搜索、打印、嵌入查看器
- **优点**：零 native 依赖、社区最大、文档最好
- **缺点**：性能和保真度不及 PDFium（大文档慢）；偏"查看"，复杂编辑弱

### 3. MuPDF（闭源商业慎用）

- **官方**：[github.com/ArtifexSoftware/mupdf](https://github.com/ArtifexSoftware/mupdf) ｜ [mupdf.com](https://mupdf.com/)
- **许可证**：**AGPL-3.0 或商业许可**（向 Artifex 购买）
- **能力**：渲染/提取/转换/合并/编辑/签名一体，支持 PDF/XPS/EPUB 等
- **生态**：Python 绑定 PyMuPDF（文本提取最强）、JS 绑定 mupdf.js
- **风险**：AGPL 网络条款——SaaS/内部 Web 也触发全应用开源

### 4. Poppler（Linux/Qt 开源场景）

- **官方**：[poppler.freedesktop.org](https://poppler.freedesktop.org/)
- **许可证**：GPL（含渲染库本身，链接即传染）
- **能力**：Qt5/Qt6/glib/cpp 多前端，成熟稳定
- **缺点**：GPL 传染；偏 Linux，Windows 依赖管理麻烦

## 二、PDF 编辑 / 处理库对比

### 许可证速查

| 许可证 | 商业友好 | 代表库 |
|---|---|---|
| Apache 2.0 | ✅ 完全 | PDFBox、qpdf、PaddleOCR、Tesseract |
| MIT | ✅ 完全 | pdf-lib(fork)、pdfplumber、Stirling-PDF(core)、pypdf |
| BSD-3 | ✅ 完全 | pypdf |
| MPL-2.0 | ⚠️ 文件级 | pikepdf |
| AGPL-3.0 | ❌ 强传染(SaaS也触发) | PyMuPDF、iText 7、Ghostscript |

### 核心库详情

| 库 | 语言 | 许可证 | 核心能力 | 活跃度 |
|---|---|---|---|---|
| **Apache PDFBox** | Java | Apache 2.0 ✅ | 创建/修改/渲染/表单/签名/加密/抽取 | 极活跃，3.0.8 |
| **qpdf** | C++ | Apache 2.0 ✅ | 线性化/加密/修复/结构变换（不做内容编辑） | 活跃，12.3.2 |
| **pypdf** | Python | BSD-3 ✅ | 纯 Python 读写/合并/拆分/加密 | 活跃 |
| **pdfplumber** | Python | MIT ✅ | 文本/表格抽取（含布局） | 活跃 |
| **pikepdf** | Python | MPL-2.0 ⚠️ | 封装 QPDF 的结构级操作 | 活跃 |
| **pdf-lib** | JS | MIT ✅ | 全平台 JS 创建/修改/合并/表单 | ⚠️原版停摆，用 fork [cantoo-scribe/pdf-lib](https://github.com/cantoo-scribe/pdf-lib) |
| **PyMuPDF** | Python | **AGPL** ❌ | 编辑+渲染+OCR 全能 | 极活跃，但需商业授权 |
| **iText 7** | Java | **AGPL** ❌ | 企业级全功能+高级模块 | 活跃，但需商业授权 |
| **Ghostscript** | C | **AGPL** ❌ | 渲染/PS转换/压缩 | 活跃，商业授权约$25k/年 |
| **Stirling-PDF** | Java | MIT(core)+专有 | 60+ 操作的完整应用平台 | 极活跃，30M+下载 |
| **PaddleOCR** | Python | Apache 2.0 ✅ | OCR（中文最佳，73k+ stars） | 极活跃，PP-OCRv6 |
| **Tesseract** | C++ | Apache 2.0 ✅ | OCR 经典，60k+ stars | 活跃，v5.5.0 |

### Stirling-PDF（重点可复用）

- **官方**：[github.com/Stirling-Tools/stirling-pdf](https://github.com/Stirling-Tools/stirling-pdf) ｜ [docs.stirlingpdf.com](https://docs.stirlingpdf.com/)
- **定位**：GitHub #1 PDF 应用，60+ 操作，30M+ 下载
- **许可证（关键）**：Open-Core
  - 核心代码 **MIT**（Copyright © 2025 Stirling PDF Inc.）
  - `app/proprietary/` 目录专有闭源（SSO/企业登录）
  - **自行构建且不含 proprietary 目录 = 纯 MIT，无用户数限制**
- **技术栈**：Java(JDK 25) + Spring Boot + Thymeleaf，前端 React，**核心引擎 PDFBox**
- **能力**：合并/拆分/转换/编辑/签名/脱敏/OCR/压缩/水印/加解密/页面操作/无代码 Pipeline/API
- **可复用性**：
  - ✅ 直接部署（Docker 一键）
  - ✅ 作为后端处理服务（桌面壳调用）
  - ✅ 作为参考架构（PDFBox + Spring Boot 如何组合）
  - ⚠️ 作为库嵌入式集成成本高（依赖栈重）

### PDF4QT（被低估的宝藏，强烈推荐）

- **官方**：[github.com/JakubMelka/PDF4QT](https://github.com/JakubMelka/PDF4QT) ｜ [jakubmelka.github.io](https://jakubmelka.github.io/)
- **许可证**：**LGPLv3**（动态链接即可闭源商业）
- **栈**：C++/Qt，自带 PDF 渲染库
- **组件**：渲染库 + Pdf4QtEditor（查看/编辑器）+ 命令行工具 + 页面操作工具
- **能力**：查看/编辑/渲染/加密/优化/高级批注/页面操作一体
- **价值**：用 Qt 做 PDF 编辑器，这是**最直接可借鉴/二次开发**的现成项目

## 四、跨平台桌面框架对比

| 框架 | 语言 | 体积 | PDF 生态 | 跨平台 | PDF 场景评分 |
|---|---|---|---|---|---|
| **Qt 6** | C++/QML/Py | 中 | 官方 Qt PDF 模块(基于PDFium) | 全平台含移动 | ★★★★★ |
| **Electron** | JS/TS | 大(80-150MB) | 极强(PDF.js 天然集成) | Win/Mac/Linux | ★★★★☆ |
| **Tauri 2.0** | Rust+Web | 极小(<10MB) | 中(Rust crate/sidecar) | 全平台含移动 | ★★★★☆ |
| **Avalonia 12** | C# | 中 | 中(社区 PDFium 绑定) | Win/Mac/Linux | ★★★★☆ |
| **WPF** | C# | 小 | 强(成熟库多) | 仅 Windows | ★★★★☆(仅Win) |
| **Flutter** | Dart | 中 | 弱(桌面 PDF 不成熟) | 全平台 | ★★★☆☆ |
| **.NET MAUI** | C# | 中 | 弱(桌面 PDF 不成熟) | 全平台 | ★★★☆☆ |

### 关键点

- **Qt 6**：官方 [Qt PDF 模块](https://doc.qt.io/qt-6/qtpdf-index.html)（`QPdfDocument`/`QPdfView`），底层 PDFium；Okular/SumatraPDF/Sioyek/PDF4QT 都基于 Qt。**综合最优解**
- **Electron**：PDF.js 零成本集成；VS Code/Obsidian 同款；缺点是体积大、内存高
- **Tauri 2.0**：体积比 Electron 小 96%、内存低 58-75%；缺点是 WebView 跨平台渲染不一致 + Rust 门槛
- **WPF**：仅 Windows 但 PDF 库最成熟（PDFiumSharp、Syncfusion、DevExpress）

## 五、推荐的 5 套组合方案

### 方案 A：PDFium + Qt 6 + PDF4QT（Windows 优先 + 极致性能 + 可闭源商业）⭐强推

- 引擎 PDFium 宽松 BSD；Qt 6 官方 PDF 模块（底层也是 PDFium）
- **PDF4QT(LGPLv3) 是现成可参考的 Qt PDF 编辑器**，动态链接即可商业
- 缺点：C++ 学习成本；LGPL 须动态链接合规
- 适合：专业 Windows PDF 软件，追求速度与保真

### 方案 B：PDF.js + Electron（跨平台 + Web 技术栈 + 快速开发）

- PDF.js 天然集成，前端开发最快；跨平台一致（自带 Chromium）
- 生态最成熟
- 缺点：体积大(80-150MB)、内存高
- 适合：功能丰富、迭代快、不在乎体积的跨平台 PDF 工具（对标 PDFgear）

### 方案 C：PDFium(WASM/Rust FFI) + Tauri 2.0（轻量 + 现代栈）

- 包体积 <10MB、内存低；Rust 后端安全高性能
- 可用 [PDFium-WASM 开源方案](https://news.ycombinator.com/item?id=44126177)
- 缺点：WebView 渲染差异、Rust 门槛、生态尚浅
- 适合：追求极致轻量、现代感、敢承担技术风险

### 方案 D：PDFium + WPF（纯 Windows + C# 团队最快落地）

- WPF PDF 库最成熟（PDFiumSharp/Syncfusion 社区版）
- C# 开发效率高、Windows 集成深
- 缺点：仅 Windows
- 适合：Windows 专属、C# 技术栈、想快速出产品

### 方案 E：Stirling-PDF + 任意桌面壳（不自己造处理逻辑）

- Stirling-PDF（MIT 社区版）做重活（转换/合并/OCR/签名）
- 桌面端只做渲染与 UI，调用本地或自托管 Stirling-PDF 服务
- 适合：需要复杂 PDF 处理但不想自己造轮子

## 六、关键决策提示

1. **许可证红线**：闭源商业避开 MuPDF(AGPL)、iText(AGPL)、Ghostscript(AGPL+$25k/年)、Poppler(GPL)；优先 PDFium(BSD)/PDF.js(Apache)；Qt 用 LGPL 须动态链接
2. **重要变化**：Evince 已被 Papers 取代（GNOME 49，2025），新项目跟踪 Papers
3. **PDFgear 虽火但闭源**，只能作为产品对标，不可复用代码
4. **SumatraPDF 用 MuPDF**，fork 需注意 AGPL 传染（想闭源商用须替换引擎为 PDFium）
5. **PDF4QT 是被低估的宝藏**：Qt + LGPLv3 + 自带渲染库 + 编辑器完整，Qt 路线最直接起点
6. **Stirling-PDF 自建剥离 proprietary 即纯 MIT**，是后端处理最优参考
7. **OCR 中文首选 PaddleOCR**（Apache 2.0，73k+ stars，中文识别强）；Tesseract 经典但中文需自训
