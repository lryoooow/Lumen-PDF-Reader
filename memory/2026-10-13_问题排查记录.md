## P0-1 另存为/合并之后「保存」必然失败，每次都弹「另存为」

- 链路：`MainWindow._do_save`(gui/main_window.py:563) → `DocumentController.save_in_place`(:247) →
  `Document.save(path, incremental=True)`(core/document.py:230) →
  `PyMuPdfEngine.save`(engines/pdf_engine.py:434) `native.save(path, incremental=True, ...)`。
- 原因：增量保存要求目标仍是 PyMuPDF 打开时绑定的原始文件。`save_as` 只改了
  `document.path`(controllers/document_controller.py:244)，原生 `native.name` 仍指旧文件；
  `merge` 之后 `native.stream` 为 True 同理。
- 复现（memory/repro_incremental_save.py）：
  - 场景 1 另存为后再增量保存 → `FileOpenError: 保存到 B.pdf 失败：incremental needs original file`
  - 场景 2 合并后增量保存 → 同样失败；场景 3 未另存为的普通增量保存 → OK
- 影响：`_do_save` 失败后恒退化为 `_on_save_as`，而该对话框默认路径为空
  (gui/main_window.py:573)，用户每次 Ctrl+S 都要重选路径。数据未丢失（`mark_saved` 未执行）。
- 测试缺口：tests/integration/test_open_render.py:130 / :143 分别测 save_as 与 save_in_place，
  没有「save_as → save_in_place」序列用例。

## P0-2 快照文件同名覆盖 → 搜索/OCR/导出静默退回磁盘旧文件

- `MainWindow._worker_source`(gui/main_window.py:504-518) 使用固定路径
  `%TEMP%/pdfreader_snapshot_<pid>.pdf`。
- 复现（memory/repro_snapshot_lock.py，另在控制器层复现）：搜索/OCR 线程已打开该快照时，
  第二次 `save_copy` 抛 `FzErrorSystem code=2: cannot remove file ...: Permission denied`。
- `_worker_source` 的 `if save_copy(tmp): return tmp` 失败时直接 `return doc.path`（磁盘旧文件），
  于是搜索/OCR/导出用的是**不含未保存批注/编辑**的旧内容，正是 CHANGELOG 0.0.2 声称已修的问题。
- 另外该快照文件从不清理，长期残留在 %TEMP%。

## P0-4 撤销「删除页」后 `meta.page_count` 不回滚 → 界面比文件少一页，被撤销回来的页看不到

- 链路：`MainWindow._on_undo`(gui/main_window.py:688) → `DocumentController.undo`(controllers/document_controller.py:303)
  → `Document.undo`(core/document.py:315) → 引擎 `journal_undo`。
- 原因：页数只在编辑动作里改（`delete_page` :199 `page_count-1`；`merge` :218 `+added`），
  `undo`/`redo`(:315-331) 只做 `engine.undo` + `invalidate_page_cache` + `mark_modified`，
  **从不回滚 `DocumentMeta.page_count`**；而 `page_count`(:87-89) 完全取自 meta。
- 复现（memory/repro_undo_pagecount.py，实测输出）：
  - 打开 3 页 → 删第 2 页（界面 2 / 引擎 2）→ 撤销 → **界面 2 页、引擎 3 页**
  - `get_page_sizes()` 只返回 2 页 → `_reload_after_change`(gui/main_window.py:696-704)
    `setup_document(2, ...)`，第 3 页在视图里彻底消失（不可滚动、不可渲染、页码/状态栏也少 1）
  - 紧接着 Ctrl+S：磁盘文件 3 页、界面 2 页；第 3 页内容仍在文件里
- 影响：静默的「所见 ≠ 所得」——用户以为撤销回来了却没看见，保存后也仍看不到，
  容易误判为「撤销没生效」再重复删除。
- 顺带：撤销后 `is_modified` 恒为 True（即使内容已回到打开时状态），关闭时仍会弹保存框。
- 相关问题：`merge` 之后引擎日志已失效（engines/pdf_engine.py:398-405 重开文档），
  `undo()` 返回 False，合并**不可撤销**且界面无任何提示（按钮仍是禁用态，行为静默）。
- 测试缺口：tests/integration/test_open_render.py:164-181 只测「撤销高亮」；
  tests/unit/core/test_document_editing.py:34-50 测了删页页数但不测「删页 → 撤销」。

## P1-4 缩放后旧页面位图不清理 → 页面错位重叠、内存不释放

- `PdfView.set_zoom`(gui/widgets/pdf_view.py:727-746) 会 `_rebuild_layout()`(:748) 重算
  `_page_y_positions` 并清空 LRU，但 `_page_items` 里仍是**旧 zoom 下渲染的 QGraphicsPixmapItem**；
  只有该页**再次渲染**时 `_update_page_item`(:659-673) 才会替换它。
- 复现（memory/repro_view_zoom.py 场景 A，实测）：3 页、zoom 1.5 渲染完 → `set_zoom(0.75)`：
  新布局应为 top=0/612/1224、页高 600，实际三个 pixmap 项仍为 top=0/1212/2424、页高 1200。
- 影响：① 缩放瞬间画面是旧图压在新布局上（重叠、错位、超出场景）；
  ② 视口外的页不会被重新渲染，旧图**长期留存**在场景里；
  ③ 清空 LRU 并不释放这些 QPixmap（scene 仍持有），大文档反复缩放内存只增不减；
  ④ 触发路径很常见：Ctrl+滚轮、适宽/适页、以及 `resizeEvent`(:863-868) 带 `_fit_mode` 时改窗口大小。
- 测试缺口：tests/unit/gui/test_pdf_view.py 只有 `_rendered_cache` 的断言(:103-110)，
  没有任何关于缩放后场景项几何的断言。

## P1-5 加密 PDF 在 GUI 里打不开，搜索/OCR/导出必然失败，另存为还会悄悄去掉加密

- (a) 打开：`MainWindow._open_path`(gui/main_window.py:897) 不传密码，
  `_on_open_failed`(:993-1000) 只弹提示；全项目没有任何密码输入框
  （`QInputDialog` 仅用于水印 :551 与便签 :676）。引擎的 `PasswordRequiredError` /
  `OpenResult.NEEDS_PASSWORD`(controllers/document_controller.py:113) 在 GUI 里没有出口。
  实测：`open_file` 无密码 → False + `openFailed('needs_password', ...)` 后戛然而止。
- (b) 后台线程拿不到密码：`_on_search_requested`(gui/main_window.py:491) 调
  `worker.setup(source, query)`，`SearchWorker.setup`(workers/search_worker.py:41) 有 `password` 形参却**从未被传入**；
  同理 `_start_ocr`(:770) `worker.setup(source, page_nums=...)`，而
  `OcrWorker.setup`(workers/ocr_worker.py:48-63) 的 docstring 明确写着「password: 加密 PDF 密码」。
  实测（memory/repro_encrypted_pipeline.py）：带密码打开后未改动 → `_worker_source` 返回加密原文件 →
  搜索直接失败「PDF 需要密码」；加了批注走快照后反而能搜（因为快照没加密）。
- (c) 加密状态丢失：`PyMuPdfEngine.save`(engines/pdf_engine.py:431-440) 增量保存用
  `PDF_ENCRYPT_KEEP`（Ctrl+S 保留加密），非增量保存 `save(path, garbage=4, deflate=True)`
  不带 encryption 参数 → 实测另存为后 `is_encrypted=False, needs_pass=0`；
  `save_copy`（内存快照，core/document.py:237）同样落地为**无密码保护**的明文 PDF 到 %TEMP%。
- 影响：① 加密文档完全无法在 GUI 里使用（等于功能缺失，却已有对应测试宣称支持）；
  ② 能打开时搜索/OCR/导出也报「需要密码」；③ 用户「另存为」后会以为仍受密码保护。

## P2 追加

- `_update_page_item`(gui/widgets/pdf_view.py:659-673) 的兜底缩放是错的：
  `setOffset(0, y)` 之后 `setScale(w/pixmap.width())` 会把 **offset 一并按比例缩放**
  （QGraphicsItem 的变换以项原点为基准），且只按宽度算的比例会同时缩放高度。
  实测（memory/repro_view_zoom.py 场景 B）：第 11 页偏移 12120 → 12093（少 27px），页越靠后错得越多。
  正常渲染路径下 pixmap 与占位差 <1px 不触发该分支，故属潜伏缺陷。
- `PdfView._words_cache`(:119) 只在 `setup_document`(:600) 清空；`MainWindow._refresh_page`
  (gui/main_window.py:681-685) 只清渲染缓存 → 插入时间戳/签名（`_on_placement` :715-729）后，
  文本选择/复制仍用旧词表（实测场景 C：文档已变仍返回旧文本）。
- `Document.undo/redo` 后 `mark_modified`(:321) 使 `is_modified` 恒为真，即使已回到磁盘上的一致状态。
- 本轮新增测试缺口汇总：① 编辑类操作的「撤销」序列（删页/旋转/合并）无任何测试；
  ② PdfView 缩放后的布局几何无测试；③ 加密文档的 GUI 打开与后台线程（搜索/OCR）无测试
  （tests/integration/test_open_render.py:42 只验证了引擎层会抛 NEEDS_PASSWORD）。
